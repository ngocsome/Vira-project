## 4. Contracts
```
PATCH /api/v1/projects/{projectId}/tasks/{taskId}
Body: { title*, description, taskType*, priority*, dueDate, estimatedHours, storyPoints, version* }
200 → ApiResponse<TaskResponse> "Cập nhật công việc thành công"
400 validation / hạn quá khứ (khi đổi hạn) | 403 không phải editor | 404 | 409 sai version

POST /api/v1/projects/{projectId}/tasks  (không đổi contract)
  + 400 "Không thể tạo công việc con cho một công việc con" khi parent có parentTask

DELETE /api/v1/projects/{projectId}/tasks/{taskId}?version=  (không đổi contract)
  Quyền: task gốc → OWNER/ADMIN; subtask → OWNER/ADMIN hoặc editor của task cha
  Cascade: xóa mềm các subtask đang hoạt động cùng mốc deletedAt

PATCH /api/v1/projects/{projectId}/tasks/{taskId}/restore?version=
  Cascade: khôi phục subtask có cùng mốc deletedAt
  + 400 "Hãy khôi phục công việc cha trước" khi cha đang bị xóa
```

## 5. Kiến trúc đích
Giữ cấu trúc module hiện tại; logic nghiệp vụ trong `TaskService`, kiểm quyền trong `TaskAuthorizationService`, entity tự cập nhật trường qua `updateDetails`.

## 6. Quyết định
- Hạn quá khứ chỉ kiểm khi đổi giá trị hạn.
- Subtask chỉ 1 cấp.
- Cascade dùng cùng `Instant` để khôi phục chính xác nhóm đã xóa cùng nhau.

## 8. Tiêu chí chấp nhận
- T1: PATCH đổi được mọi trường; version tăng; sai version → 409; MEMBER không liên quan → 403.
- T2: tạo subtask của subtask → 400; editor task cha xóa được subtask; MEMBER khác → 403; xóa cha ẩn subtask; khôi phục cha hiện lại subtask.
- T3: nút "Chỉnh sửa" chỉ hiện khi có quyền; lưu xong UI cập nhật ngay trên board và modal.
- T4: liệt kê/tạo/xóa/mở subtask trong TaskDetails.
- T5: suite mới pass; suite cũ không hồi quy.

## 9. Edge cases
- Tiêu đề rỗng / chỉ khoảng trắng → 400.

- Story point âm, giờ ≤ 0 → 400.
- Sửa đồng thời (2 tab) → 409, UI báo lỗi và tải lại task.
